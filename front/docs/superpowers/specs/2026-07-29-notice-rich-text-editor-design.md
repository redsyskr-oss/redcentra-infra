# 공지사항 리치 텍스트 편집기 설계

## 목표

공지사항 등록과 수정 화면에 Tiptap 기반 HTML 편집기를 적용한다. 이미지는 본문에 삽입하고 PPT, Excel, Word, PDF, 한글 문서는 첨부파일로 제공한다. 관공서 업무 화면에 필요한 접근성, 파일 검증, 안전한 HTML 표시를 포함한다.

## 범위

### 포함

- 신규 공지 등록과 기존 공지 수정에서 동일한 편집기 사용
- 제목 단계, 굵게, 밑줄, 정렬, 글머리표, 번호 목록
- 링크와 표 삽입 및 기본 행·열 조작
- 실행 취소와 다시 실행
- Word 등 외부 문서에서 복사한 서식 있는 내용 붙여넣기
- 이미지 업로드, 대체 텍스트 입력, 본문 삽입
- PPT, Excel, Word, PDF, 한글 문서 첨부
- 기존 첨부파일 표시, 유지, 삭제
- 저장된 HTML의 허용 목록 기반 정제 및 표시
- 키보드 조작과 스크린 리더용 레이블
- 업로드 상태, 부분 실패, 재시도 안내

### 제외

- Office 파일을 브라우저에서 직접 편집
- Office 파일 미리보기 또는 HTML 변환
- 실시간 공동 편집
- 댓글, 변경 이력, 결재 워크플로
- Tiptap 유료 확장 기능

## 기술 선택

Tiptap의 MIT 라이선스 오픈소스 패키지를 사용한다. React 바인딩과 필요한 오픈소스 확장만 설치하고, 관공서 공지 작성에 필요한 제한된 툴바를 자체 UI로 구성한다.

CKEditor 5는 완성도와 접근성이 우수하지만 GPL 2+ 또는 상용 라이선스 검토가 필요하므로 이번 구현에서는 제외한다. 단순 `contenteditable` 방식은 표, 이미지, 접근성 및 유지보수 비용 때문에 제외한다.

## 컴포넌트 구조

- `Notice.tsx`
  - 공지 목록 조회와 선택
  - 등록, 수정, 삭제 mutation
  - 등록·수정 다이얼로그 상태
- `notice/types.ts`
  - 공지, 공지 입력값, 첨부파일 타입
- `notice/NoticeFormDialog.tsx`
  - 제목, 게시 기간, 상단 고정
  - 본문 편집기
  - 첨부파일 선택, 기존 첨부 유지·삭제
  - 저장 및 오류 표시
- `notice/NoticeEditor.tsx`
  - Tiptap 초기화와 HTML 값 동기화
  - 접근 가능한 툴바
  - 표와 링크 명령
  - 이미지 선택, 대체 텍스트 입력, 삽입 요청
- `notice/NoticeContent.tsx`
  - 정제된 공지 HTML 표시
  - 첨부파일 다운로드 목록
- `notice/content.ts`
  - HTML 정제
  - 안정적인 이미지 URL 생성 및 검증
- `notice/file-validation.ts`
  - 허용 확장자, MIME, 파일 크기 검증

기존 `src/components/ui`의 shadcn/ui 파일은 직접 수정하지 않는다.

## 데이터 흐름

### 등록

1. 사용자가 본문과 파일을 편집한다.
2. 클라이언트에서 필수값과 파일을 검증한다.
3. 공지 생성 API를 호출해 `noticeId`를 얻는다.
4. 선택한 파일을 `NOTICE_ATTACHMENT`, `refType`, `refId`와 함께 업로드한다.
5. 이미지 업로드 결과의 `fileId`를 안정적인 동일 출처 이미지 URL로 변환한다.
6. 본문의 임시 이미지 표시를 안정적인 URL로 교체하고 공지 본문을 갱신한다.
7. 목록 캐시를 무효화하고 생성된 공지를 선택한다.

공지 생성 성공 후 일부 파일 업로드가 실패하면 생성된 공지는 유지한다. 실패한 파일 이름과 원인을 표시하고 사용자가 수정 화면에서 재시도할 수 있게 한다.

### 수정

1. 선택한 공지의 제목, 본문, 게시 기간, 고정 여부와 기존 첨부를 폼에 채운다.
2. 새 파일을 검증하고 사용자가 제거 표시한 기존 첨부를 별도로 추적한다.
3. 공지 수정 API를 호출한다.
4. 새 파일을 해당 `noticeId`에 업로드한다.
5. 제거 표시된 기존 첨부를 삭제한다.
6. 이미지 참조가 바뀌면 최종 HTML로 공지를 한 번 더 갱신한다.
7. 상세 및 목록 캐시를 무효화한다.

삭제 API가 실패한 기존 첨부는 UI에서 삭제 완료로 표시하지 않는다.

### 상세 표시와 다운로드

공지 본문은 렌더링 전에 정제한다. 첨부파일 다운로드는 `fileId`로 presigned URL을 발급받은 뒤 브라우저 다운로드를 시작한다. 본문 이미지는 만료되는 presigned URL을 HTML에 저장하지 않고 동일 출처의 안정적인 애플리케이션 URL을 저장한다.

## 백엔드 API 계약

현재 프런트에는 다음 파일 API 계약이 존재한다.

- `POST /api/v1/files/presigned-upload`
- presigned URL에 `PUT`
- `POST /api/v1/files/confirm`
- `GET /api/v1/files/{fileId}/presigned-download`

구현 중 백엔드에서 다음 계약의 실제 제공 여부를 확인한다.

- 공지 수정 `PUT` 또는 `PATCH /api/v1/notices/{noticeId}`
- 공지별 첨부 조회
- 첨부 삭제
- 인증을 유지하면서 이미지를 응답하거나 presigned URL로 리다이렉트하는 안정적인 동일 출처 이미지 경로

없는 계약은 임의로 정상 동작한다고 가정하지 않는다. 프런트 타입과 호출 경계를 구현하되, 필요한 백엔드 API 명세와 미지원 상태를 결과에 명시한다.

## HTML 보안

공지 상세는 원본 HTML을 바로 `dangerouslySetInnerHTML`에 전달하지 않는다. 정제기는 다음 원칙을 따른다.

- 허용 태그만 유지: 문단, 제목, 강조, 밑줄, 목록, 링크, 표, 이미지 등 편집기가 생성하는 제한된 집합
- `script`, `style`, `iframe`, `object`, `embed`, 폼 요소 제거
- `on*` 이벤트 속성과 임의 `style` 제거
- 링크와 이미지 URL은 `https`, 동일 출처 상대 경로 등 허용 스킴만 유지
- 외부 링크에는 안전한 `rel` 속성 적용
- 이미지에는 대체 텍스트 제공

서버도 동일하거나 더 엄격한 정제를 적용해야 하며, 클라이언트 정제만으로 보안 경계를 완성했다고 간주하지 않는다.

## 파일 정책

- 본문 이미지: PNG, JPEG, WebP
- 일반 첨부: PPT/PPTX, XLS/XLSX, DOC/DOCX, PDF, HWP/HWPX
- 확장자와 MIME을 함께 확인하되 MIME이 비어 있는 정상 브라우저 파일도 확장자로 보완 판단
- 파일명은 화면에 텍스트로만 표시
- 파일 크기 제한은 백엔드 정책을 기준으로 상수화하고 UI에 명시
- 업로드 중 저장 버튼을 비활성화해 중복 제출 방지

정확한 최대 파일 크기가 백엔드 계약에 없으면 구현 시 기존 업로드 정책을 확인하고, 확인되지 않으면 임의 값으로 차단하지 않고 서버 오류를 사용자 친화적으로 표시한다.

## 접근성

- 편집 영역에 명확한 레이블과 `role="textbox"` 제공
- 툴바에 `role="toolbar"`와 접근 가능한 이름 제공
- 버튼마다 동작 이름, 단축키 힌트, 토글 상태 제공
- 키보드만으로 툴바 진입, 버튼 이동, 편집 영역 복귀 가능
- 이미지 삽입 전에 대체 텍스트 입력 요구
- 색상만으로 활성, 오류, 업로드 상태를 구분하지 않음
- 표 삽입 기능의 행·열 입력에 레이블 제공
- 저장 오류 발생 시 포커스 가능한 오류 요약 제공

## 오류 처리

- 공지 API 실패와 파일 업로드 실패를 구분해 표시
- 등록 자체가 실패하면 파일 업로드를 시작하지 않음
- 업로드 일부 실패 시 성공한 공지와 파일은 유지하고 실패 목록 제공
- 수정 실패 시 다이얼로그와 사용자 입력 유지
- 다운로드 URL 발급 실패 시 해당 파일에 오류 표시
- 삭제 확인 후 공지 또는 첨부 삭제 수행

## 테스트 전략

테스트 우선 개발로 각 핵심 동작의 실패를 먼저 확인한다.

- HTML 정제
  - 위험한 태그와 이벤트 속성 제거
  - 안전한 표, 목록, 링크, 이미지 유지
  - 위험한 URL 제거
- 파일 검증
  - 허용 이미지와 Office 문서 수락
  - 실행 파일과 미허용 확장자 거부
  - 파일명 대소문자 처리
- 공지 입력 변환
  - 등록과 수정 payload에 HTML과 게시 정보 포함
  - 기존 첨부 유지·삭제와 새 첨부 구분
- 편집기
  - 초기 HTML 표시
  - 내용 변경 전달
  - 접근 가능한 툴바 이름과 버튼 상태
- 등록·수정 흐름
  - 공지 생성 후 파일 업로드 순서
  - 일부 업로드 실패 시 공지 유지와 오류 표시
  - 수정 시 기존 값 채움

완료 전 전체 테스트, ESLint, TypeScript가 포함된 프로덕션 빌드를 새로 실행한다.

## 완료 기준

- 등록과 수정에서 동일한 Tiptap 편집기가 동작한다.
- 공지 상세에 안전하게 정제된 서식 본문이 표시된다.
- 이미지에 대체 텍스트가 있으며 본문에서 만료되지 않는 참조를 사용한다.
- 허용된 Office, PDF, 한글 문서를 첨부하고 내려받을 수 있다.
- 기존 첨부를 유지하거나 삭제할 수 있다.
- 핵심 보안 및 파일 검증 테스트가 통과한다.
- lint와 프로덕션 빌드가 통과한다.
- 백엔드 미지원 API가 있으면 구현 결과에 정확히 명시한다.
